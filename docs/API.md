# API Pina.market

JSON сессии на одном домене. GET `/api/config/` возвращает CSRF-токен; каждый POST передаёт его в `X-CSRFToken`. Сервер не включает CORS. Вход обновляет ID сессии и CSRF; смена/восстановление пароля отзывает прежние сессии через auth_version. Клиент видит только собственные операции. Все `/api/admin/` требуют серверной роли сотрудника.

| Маршрут | Метод | Назначение |
|---|---|---|
| config/ | GET | Серверный режим и CSRF |
| register/ | POST | Email → временный пароль письмом |
| login/ | POST | Email и пароль → сессия |
| logout/ | POST | Завершить сессию |
| password/ | POST | Сменить пароль либо skip первого предложения |
| forgot/ | POST | Запросить одноразовую ссылку восстановления |
| reset/ | POST | Token и новый пароль |
| state/ | GET | Клиент, баланс, каталог, последние заявки и уведомления |
| catalog/ | GET | Каталог без скрытых сервисов |
| deposits/ | POST | Создать заявку с UUID-ключом идемпотентности |
| orders/ | POST | Проверить версию условий, сумму, регион и зарезервировать |
| operations/ | GET | Реестр с фильтрами и CSV |
| orders/{id}/reply/ | POST | Ответ на требуемое уточнение |
| notifications/read/ | POST | Отметить уведомления прочитанными |
| admin/operations/{id}/ | POST | confirm, take, complete, clarify, cancel |
| admin/clients/ | GET | Клиенты, поиск и пагинация |
| admin/clients/{id}/notify/ | POST | Персональное уведомление в кабинет |
| admin/services/ | GET | Все сервисы для сотрудника |
| admin/services/{code}/ | POST | Изменить статус и условия с проверкой версии |
| admin/settings/ | GET / POST | Адрес кассы и включение внесения наличных |
| admin/clients/{id}/refund/ | POST | Резерв для банковского возврата аванса |
| admin/mail-test/ | POST | Письмо на email текущего сотрудника для проверки SMTP |

Реестр: kind, status, from, to, min, max, client, page, number; scope=admin доступен только сотрудникам. export=csv выгружает результат всех фильтров. Даты фильтруются по дням Europe/Moscow, хранятся в UTC. Денежные значения ответа — целые копейки. Ввод amount/min/max — десятичная строка RUB не более двух знаков. Комиссия feeBps — сотые доли процента. version защищает от принятия устаревших условий.

При создании заявки вносится номер из общей заблокированной строки счётчика. Остатки и резервы меняются в InnoDB-транзакции с SELECT FOR UPDATE; отдельные уникальные ограничения контролируют ключ запроса, банковское основание и финансовое событие. Отдельный неизменяемый журнал содержит delta по балансу и резерву. Это журнал аванса, а не банковский счёт или самостоятельная платёжная система.

Успешный ответ SMTP означает принятие письма сервером отправки, а не гарантированную доставку во входящие. Для реального домена нужно проверить доставку, записи DNS и ограничения хостинга. Веб-установщик не отправляет никаких писем сам по себе.

Регистрация требует accepted=true и актуальную version из app/legal.json; при заказе передаются accepted=true и legalVersion. Редакция согласия и хеш документов сохраняются в pm_consents, а условия и редакция договора — в снимке заказа.

Банковский возврат создаётся сотрудником в карточке клиента: сумма резервируется, kind=refund и status=in_progress. После реальной выплаты сотрудник завершает заявку действием complete с уникальным bankref и подтверждением в text; сумма списывается один раз. Отмена до выплаты освобождает резерв. API не инициирует перевод в банке сам по себе.
