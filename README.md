# Pina.market

Сайт организации оплаты иностранных цифровых сервисов. PHP 8.2+, MySQL 5.7+/8 или MariaDB с InnoDB, Apache с mod_rewrite. Подходит для обычного Linux-хостинга reg.ru с PHP и доступом к терминалу. На сервере не нужны Node.js, Docker, Composer или Python.

## Установка через Bash

В терминале **Bash** хостинга вставьте одну команду:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/gselfman/pinamarket/main/deploy/bootstrap.sh)
```

Установщик скачает код в `$HOME/pinamarket-code` (Git либо архив) и запустит настройку. При повторном запуске обновит существующую установку, сохранив её настройки. Если предпочитаете видеть отдельные шаги:

```bash
git clone https://github.com/gselfman/pinamarket.git "$HOME/pinamarket-code"
cd "$HOME/pinamarket-code"
bash deploy/install.sh
```

Скрипт последовательно запросит адрес сайта, **полный путь к каталогу домена из панели reg.ru**, MySQL, SMTP и выбранные email/пароль администратора. Пароли вводятся интерактивно и не записываются в историю команд. Исходники и app/config.php остаются вне публичного каталога. Скрипт проверяет расширения PHP, создаёт таблицы, отправляет проверочное письмо, создаёт администратора, копирует файлы и проверяет HTTPS/API.

Если PHP CLI не найден автоматически:

```bash
PINA_PHP_BIN=/opt/php/8.2/bin/php bash deploy/install.sh
```

Сначала можно проверить PHP:

```bash
bash deploy/install.sh --check
```

### Что подготовить в панели reg.ru

1. Домен/поддомен должен быть добавлен и направлен на хостинг. В панели включите PHP 8.2+ с PDO MySQL, mbstring, OpenSSL и sessions. Активируйте SSL/HTTPS.
2. Нужна отдельная доступная MySQL-база и пользователь с правами на неё. Скопируйте из панели полное имя с префиксом логина, адрес сервера и пароль. Скрипт создаёт таблицы **в существующей базе**. Общий хостинг обычно не даёт приложению право создавать базы или пользователей за пределами панели.
3. Для отправки писем подготовьте SMTP-хост, логин, пароль и порт 465/SSL либо 587/STARTTLS. Адрес отправителя должен соответствовать разрешённому почтовому ящику. Проверьте SPF/DKIM/DMARC по настройкам почтового провайдера.
4. Если в каталоге домена уже есть сайт, скрипт потребует ввести `ЗАМЕНИТЬ` и создаст полный архив файлов рядом с исходниками, вне публичного каталога. Если архив создать не удалось, файлы не заменяются. Первая публикация переключает каталог целиком: прежнее приложение остаётся в соседней приватной папке `.pinamarket-previous-ДАТА`; `.well-known` сохраняется для проверки SSL. Старые папки admin/api не смешиваются с новым приложением. Для базы действующего сайта дополнительно сохраните экспорт через панель/phpMyAdmin.

Нельзя автоматически создать домен, включить SSL или получить доступ к базе без прав панели reg.ru. Скрипт не имитирует эти действия. Он останавливается с понятной ошибкой, если доступ или настройки отсутствуют.

Официальная справка reg.ru: [SSH](https://help.reg.ru/support/hosting/dostupy-i-podklyucheniye-panel-upravleniya-ftp-ssh/rabota-po-ssh-na-virtualnom-hostinge), [PHP](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/kak-smenit-versiyu-php-na-hostinge), [создание MySQL](https://help.reg.ru/support/hosting/cms/ustanovka-wordpress).

## После установки

Администратор: `https://pina.market/admin/` или `/admin/` на выбранном домене. В пользовательском кабинете ссылки на админку нет; права проверяются сервером. Клиенты входят через `/login/` и регистрируются через `/register/`.

В админке:

- «Настройки» — внесение наличных и подтверждённый адрес кассы. При пустом адресе внесение отключено. Не используйте юридический адрес банка как адрес кассы без подтверждения.
- «Сервисы» — установите реальные продукт/номинал, регионы, описание, инструкцию, комиссию, лимиты и срок в условиях. Первоначально сервисы недоступны. Для включения обязательны инструкция, условия и регионы.
- «Заявки на пополнение» — сверьте поступление с выпиской, введите уникальный банковский идентификатор и точную фактическую сумму, подтвердите. Создание заявки само по себе не зачисляет деньги.
- «Оплата сервисов» — возьмите заявку в работу, исполните её и укажите результат либо запросите уточнение. Ответ клиента возвращает заявку в очередь. Отмена освобождает резерв.
- «Клиенты» — поиск ID/email и персональные уведомления в кабинет.
- Реестры — фильтры статуса, дат, суммы, клиента, по 20 записей на странице; CSV содержит весь отфильтрованный результат.

Проверочное письмо установщика подтверждает принятие SMTP-сервером, а не гарантированную доставку во входящие. Проверьте фактическое получение, регистрацию своим email, вход по временному паролю, смену пароля, внесение, заказ и выгрузку на вашем домене.

## Как работает учёт

ID клиентов: `1000, 1001, 1014, 1027…`. Администратор первой установки получает 1000. Все следующие ID — следующие кратные 13. Номера операций независимы и последовательны от 1000.

Баланс — аванс в RUB. При заказе сумма резервируется; после подтверждения исполнения резерв списывается. Отмена возвращает резерв в доступный остаток. Все суммы хранятся в копейках, изменения выполняются в InnoDB-транзакциях с блокировкой клиента. Повторные запросы, банковские основания и финансовые события защищены уникальными ограничениями. Изменения и сообщения сохраняются на сервере; локального режима и вымышленных аккаунтов в приложении нет.

Регистрация отправляет временный пароль и ссылку на обычную страницу входа. Первый вход — за 24 часа. При первом входе можно изменить пароль либо пропустить предложение. Восстановление — одноразовая ссылка на 1 час. Принятие редакции юридических документов записывается с её версией и хешем.

## Обновление

```bash
cd "$HOME/pinamarket-code"
git pull --ff-only
bash deploy/install.sh --update
```

Обновление сохраняет app/config.php, клиентов и операции, создаёт архив публичных файлов и не создаёт администратора повторно. Активный PHP-код находится в отдельной приватной версии var/releases; git pull не меняет работающий backend до завершения установки. При провале итоговой HTTPS-проверки установщик восстанавливает прежний сайт или предыдущую версию приложения. Перед изменениями базы сделайте её экспорт. Не откатывайте код поверх несовместимой схемы. Резервные копии остаются вне сайта.

Планировщик можно использовать для очистки технических записей раз в сутки:

```bash
/opt/php/8.2/bin/php "$HOME/pinamarket-code/deploy/maintenance.php"
```

## Код и проверка

- `dist/` — интерфейс и оригинальный логотип, готовые файлы без сборки на хостинге.
- `app/` — API, SMTP, учёт, тексты документов и каталог; приватный config.php не коммитится.
- `public/` — публичный вход и правила Apache; реальный путь app задаётся установщиком.
- `database/schema.sql` — схема InnoDB.
- `deploy/install.sh`, `deploy/setup.php` — установка/обновление без root.
- `tests/`, `.github/workflows/checks.yml` — проверки PHP и MySQL.

```bash
php tests/unit.php
php -l app/api.php
node --check dist/app.js
bash -n deploy/install.sh
```

GitHub Actions проверяет отдельную MySQL-базу, регистрацию, ID, согласия, права, идемпотентность, зачисления, резервы, уточнения, отмену, исполнение и фильтры. Тестовые адреса существуют только в tests/, не в рабочей базе.

## Документы и обслуживание

Клиентские документы открываются в кабинете и по `/documents/terms/`, `/documents/privacy/`, `/documents/refund/`, `/documents/cookies/`, `/documents/tariffs/`, `/documents/requisites/`, `/documents/consent/`. Единственный источник — app/legal.json; копия для интерфейса — dist/legal.js. При изменении содержания обновляйте версию и оба представления согласованно.

Договор составлен для Pina Market LLC из предоставленных реквизитов. Перед приёмом реальных платежей владелец проверяет фактические банковские условия, тарифы поставщиков, требования к странам обслуживания и обработке данных. Наличие документов само по себе не является банковским согласованием или юридическим заключением. Серверы банка и сервисов не интегрированы автоматически: перечисления, выдача цифровых продуктов и сверка выполняются сотрудником.

Возврат свободного аванса запрашивается через поддержку. В «Клиенты» нажмите «Возврат», укажите сумму, основание и проверенные реквизиты: сумма резервируется. После фактической банковской выплаты откройте «Возвраты» и подтвердите её уникальным номером. Отмена до выплаты освобождает резерв. Нельзя возвращать деньги путём удаления операции или произвольной правки баланса. Для банковского возврата предусмотрен резерв и отдельная запись учёта; порядок описан в административной инструкции.
